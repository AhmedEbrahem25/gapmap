# Database guide

## Engines

| Where | Engine | How it is chosen |
|---|---|---|
| Docker Compose | PostgreSQL 16 (`pgvector/pgvector:pg16` image) | `DATABASE_URL` is set by `docker-compose.yml` |
| Local runs | SQLite file `backend/gapmap.db` | Default when `DATABASE_URL` is not set |
| Automated tests | SQLite in memory | Set up by `backend/tests/conftest.py` |

The models use portable types (UUID, JSON, enums stored as strings), so one schema runs on both. CI
runs the unit tests on SQLite and the smoke test on PostgreSQL.

## Schema

Defined by the SQLAlchemy models in `backend/app/models/` and drawn in [ERD.md](../04-Design/ERD.md).
The schema is created with `Base.metadata.create_all`. **There are no migrations** (ADR 0001 §3).
After any model change, reseed.

## The seed

```bash
python -m app.seed               # full demo state, results already approved
python -m app.seed --no-results  # same, but leaves the results to be imported live
```

Inside Docker, prefix with `docker compose exec backend`.

**The seed wipes the database and the uploaded files**, then creates:

| Data | Content |
|---|---|
| Users | 1 instructor, 1 second instructor (for permission tests), 1 coordinator, 1 admin, 20 students `STU001`–`STU020` with `stu001@gapmap.test` … |
| Course | *Software Engineering (SE301)*, all 20 students enrolled |
| Lecture | A 12-slide PDF generated by `app/seed/lecture_pdf.py`, processed like an upload: text and page images |
| Concepts | Agile, Scrum Roles, Requirements, each with approved slide mappings |
| Exam | *Midterm Quiz 1*: 9 MCQs, 3 per concept, key approved, wrong options tagged with error types |
| Question bank | 3 practice + 3 retest items per concept (approved), plus 1 pending AI draft (TC-25) |
| Results | `data/sample/exam1_results.csv` imported and approved (skipped with `--no-results`) |

The seed does not run the analysis. Click **Run analysis** on the course page, or call
`POST /api/exams/{id}/analyze`.

All demo accounts share the password in `DEMO_PASSWORD` (`.env`). They are synthetic test users.

## Sample data files

| File | What it is |
|---|---|
| `data/sample/exam1_results.csv` | Clean results: 20 students × 9 questions = 180 rows |
| `data/sample/exam1_results_with_errors.csv` | The same with 3 errors (an answer outside the options, an unknown question, a duplicate) and 1 warning (a score that disagrees with the key) |
| `data/templates/results_template.csv` | Empty template for instructors |

The results were generated by `app/seed/generate_results.py`, so most of the class misses Scrum Roles
and STU001 misses Q1, Q2, Q4 and Q5.

## Inspecting the data

PostgreSQL in Docker:

```bash
docker compose exec db psql -U gapmap -d gapmap
```

Then, for example: `select action, timestamp from audit_logs order by timestamp desc;`

SQLite locally: open `backend/gapmap.db` with any SQLite browser, or `sqlite3 backend/gapmap.db`.

## Backup and restore (PostgreSQL)

```bash
docker compose exec db pg_dump -U gapmap gapmap > backup.sql
docker compose exec -T db psql -U gapmap -d gapmap < backup.sql
```

Uploaded lectures and page images are in the `storage` volume, not the database; back up both.

## Settings that affect analysis

In `backend/app/core/config.py`, each can be overridden from `.env` by its upper-case name:

| Setting | Default | Meaning |
|---|---|---|
| `WEAK_THRESHOLD_PERCENT` | 60 | Below this a concept needs review |
| `MIN_QUESTIONS_PER_CONCEPT` | 2 | Fewer questions = "not enough data" |
| `RETEACH_ERROR_RATE_PERCENT` | 40 | Class error rate at which a concept is suggested for re-teaching |
| `MAX_UPLOAD_MB` | 25 | Lecture file size limit |
